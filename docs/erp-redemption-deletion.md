## 本系统流程

1. 在任务明细每行操作中点击“删除配置”。服务器获取当前真实配置、组身份和指纹，生成持久化预览，列出盘口、配置 ID、指定码和全部共享批次。
2. 取消后不提交删除；保留预览，不改变原任务和库存状态。点击带配置 ID 的真删除确认后，服务器重新核对预览版本、五分钟有效期、任务参数、共享范围及账号删除能力。
3. 本地事务先保留 `DELETING` 记录，将共享所有者标为删除处理中；随后通过主 API 的统一远端账号、凭据和会话执行。主 API 原子领取一次性执行记录，重复 HTTP 请求无法再次领取。删除写请求不自动重新登录重放。
4. 远端先核对目标身份指纹再发送一次原生 DELETE。删除后必须成功读取空结果，并通过两次完整、分页及数量一致的目录核验确认原 ID 消失，才登记 `DELETED`。
5. 超时、响应不明、仍存在或分页/权限异常保留 `UNKNOWN`。页面仅提供“核对删除结果”；后续操作只读，不自动重放 DELETE。原任务关联、配置 ID、码、库存、发布记录和审计保留。
6. 共享任务投影为“远端配置已删除”或“删除结果待核对”，禁止继续发布、下载、导入、完整导出、修改奖励、同码复用或缺失自动重建。历史库存不作为当前可用库存返回。其他未受影响配置仍可通过已有的部分导出流程导出。

该功能只处理本系统已登记的远端配置；没有新增清库或删除本地历史任务的入口。主动删除与配置意外缺失分别处理。未知结果仍存在时保持阻断；后续再次删除或重建需要另外明确设计和确认，不复用旧删除授权。

## 权限与迁移

- 两层服务均要求本地兑换码管理及生成权限，远端还需独立的 `ERP_REDEMPTION_DELETE` 与 `ERP_REMOTE_CHECK` 能力。删除能力默认关闭，不随创建、奖励修改或共享账号自动获得。
- `0059` / Flyway `V34` 新增删除日志表、一次性执行标记及所有者删除状态字段；不删除已有行、不清理库存、不关闭保护触发器。持久化记录后不允许破坏性结构降级。
- 当前为本地实现。此次没有连接 ECS、迁移生产或部署本功能。生产上线需要新的备份/执行窗口确认，并通过项目发布脚本先完成 0059 结构迁移。
- 实测中删除的 3590 是通过远端原生页面删除，发生在本功能上线之前，不会已有本系统删除日志；现有生产版本仍按其既有缺失配置流程工作。不要将它当作本系统删除状态已同步的验收结果。

## 任务行批量删除

任务列表右侧固定“操作”列新增红色“批量删除”，范围由服务端根据主任务 ID 解析，覆盖全部盘口、日期和档位，包括任务复用的历史配置。以盘口 ID 加配置 ID 去重；不同盘口的相同数字 ID 不会合并。未登记有效远端 ID 的明细列为未创建，不向远端发送删除请求。

独立窗口逐条读取配置并检查删除权限，列出配置 ID、码、任务奖励、日期和全部共享任务编号。其他任务共享同一配置时单独突出提示。预览期间没有远端删除写入；需勾选确认并输入当前任务编号，才授权本轮具体清单。任务范围变动、远端指纹改变、共享引用或配置参数变化会阻止执行，不能沿用旧确认删除新配置。

任务级日志也包含在尚未上线的 0059 / V34 中。预览与进度保存到 `erp_compat_redemption_task_deletions`，不存放会话或凭据。每个已认证请求最多推进一个配置，沿用统一账号会话和默认关闭的删除能力。重复并发推进由持久化 busy 标记拦截；远端提交继续使用单条删除的一次性执行记录。前一条删除造成的批次计数和版本更新不应阻止下一条，但配置参数、明细版本、共享关联和远端指纹必须保持确认时的事实。

窗口关闭后停止提交后续配置，已经提交的请求继续完成核验；重新打开只展示已确认任务的进度，不自动继续远端写入。用户可继续原清单未执行项、刷新进度，或只读核对结果。请求结果不明立即暂停本轮后续执行，禁止自动重放 DELETE；失联占用超过等待期后可只读核对并释放本轮占用，重新预览未完成项仍需再次确认。

针对已被外部删除但仍被原任务引用的有效配置 ID：必须通过既有严格缺失证明读取为 ABSENT，确认后再独立回读；持续缺失时只登记主动删除状态，不发送 DELETE。其历史库存、旧 ID 和共享引用保留，全部共享任务禁止按缺失自动重建；如果重新读到了配置则结果待核对，不能临时改为删除它。页面逐条区分“已删除并核验”和“远端原本已不存在”。没有有效配置 ID 或无法读取的明细不能当作已删除。

批量结果保留每一项状态，部分失败不显示全部成功。现阶段按浏览器主动推进执行，未引入后台服务持有登录会话的队列；关闭窗口后继续整批后台执行不在本次实现范围。

本轮批量实现验证：Java 全量 237 项通过；前端兑换码流程 78 项通过；删除适配器、主执行器与 0059 迁移 10 项 Python 测试通过；前端类型检查与生产构建通过。Java 删除流程及统一执行器另外复验 29 项通过。Playwright 使用本地合成数据核对任务操作列、共享任务提示、确认输入与关闭窗口，未连接真实远端。截图和验收记录见 `output/playwright/task-deletion/`。本轮没有真实删除、生产连接、部署或迁移。

## 2026-11-13 中断恢复复核（设计缺口，尚未实现补齐）

复核依据为已发布源码归档与上述只读证据，未重新执行生产业务操作。现有实现持久化单项执行和批量进度；重新预检保留DELETED、UNKNOWN，只将通过新预检的CHECKED项纳入再次确认后的执行。UNKNOWN项不会因重新预检而再次发送DELETE。

已证实的缺口：RedemptionDeletionService.reconcile读到PRESENT仍只保存UNKNOWN，没有保存这次观察结果和核验时间，也没有明确失败后独立重新确认的入口。批量reconcile合并不同未决原因；不能单凭批量FINISHED表示全部删除成功。原生权限补丁不解决这些恢复与展示缺口。

待补契约：分开保存执行事实和远端当前事实，以盘口、原配置ID和组身份定位，不能仅凭同码定位；保存每次只读核验时间、证据摘要、存在性和身份变化。严格确认原配置不存在时登记并跳过，不能推断是谁删除或已发布码必然失效。读到原配置仍存在时明确显示仍存在；权限、网络、分页不完整则显示无法确认。出现同码新ID或组身份变化时，不得把新配置纳入原删除范围。

恢复应先核对，再分别展示已不存在、仍存在、未提交、无法确认。未提交项可重新预检并确认继续。曾尝试且仍存在的项，须确认旧请求已终止或有明确未发送/拒绝证据，再允许用户独立确认新尝试，保留旧记录并关联新尝试；仅PRESENT或等待超时不足以自动重发。无法确认项继续只读核对，可明确排除后处理其他已核验项；有遗留项必须显示部分完成。

回归范围：服务端已删除但响应丢失；明确拒绝后仍存在；旧请求仍执行；同码重建为新ID；分页/权限失败；重开窗口和重启后进度保留；已删除项零重发；未知项被排除时其他未提交项可继续；存在未决项不能显示全部成功。此段是复核与待实现契约，不代表相关入口已上线。
