# 统一远端账号接管说明

## 目标结构

- `SourceConfig` 只作为盘口主数据，保存 Base URL、时区、币种和盘口级只读 API 配置。
- `RemoteAccount` 是分析与 ERP 共用的唯一登录账号记录；创建账号时必须选择所属盘口。
- 一个盘口可以有多个账号，但最多只有一个 `is_default=true` 的默认账号。
- 自动同步、数据字典读取和对账使用盘口的默认账号；ERP 任务仍可明确选择同盘口下的其他启用账号。
- 所有统一账号固定具备完整能力集合。服务端继续逐项校验能力和全局执行开关，但管理界面不再提供逐项勾选。

## 0038 迁移行为

`20260828_0038` 只变更本地结构和授权元数据，不解密、不复制凭据，也不调用任何远端系统：

1. 新增 `remote_accounts.is_default`。
2. 每个盘口优先把现有 `LEGACY_SOURCE` 账号设为默认；没有历史账号时选择最早的启用账号。
3. 建立“每盘口最多一个默认账号”的数据库唯一约束。
4. 为已有账号补齐全部服务端能力记录。

## 管理员接管步骤

1. 在“盘口配置”确认盘口 Base URL、时区、币种和盘口级 API 配置。
2. 进入“远端账号”，逐个打开标记为“待重新配置”的历史账号。
3. 重新填写登录账号、密码和 TOTP Secret。保存后记录从 `LEGACY_SOURCE` 转为 `MANAGED`，后续分析和 ERP 都使用该账号密文。
4. 每个盘口至少保留一个已启用的默认账号；需要切换时，在目标账号上开启“默认账号”，系统自动取消原默认账号。
5. 确认默认账号可用后，再在“盘口配置”中启用盘口。

历史 `SourceConfig.encrypted_credentials` 在接管期仅作为旧账号桥接和回退材料保留；统一解析器在默认账号转为 `MANAGED` 后不会再读取它。清理历史密文应在全部盘口接管验收完成后另行规划，不包含在 0038 中。

## 发布边界

本变更当前只完成代码、迁移文件和本地验证。生产执行 0038、应用发布、账号重新录入以及任何连接测试或远端业务操作，仍需按生产备份、回退和执行窗口流程分别授权。
