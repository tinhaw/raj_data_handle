## 2. 跨模块的真实业务规则

1. **时区和数据范围是业务规则。** ERP 固定使用业务时区展示时间；用户除了功能权限外，还受到投放公司范围限制。
2. **审计不可省略。** 登录、主数据、日结、导入、锁账、权限、兑换码和远端动作都保留操作者、时间、对象、请求 ID、范围和前后变化。
3. **金额并非只有一张日结表。** 期初/期末是时点余额，转 U、消耗、汇损、服务费、回流、退款、其他和欺诈扣减是发生额；报表不得把每日结余重复累计。
4. **远端动作是可恢复的任务流程。** 远端创建、发布和下载都必须有独立状态、进度、错误原因、并发保护和审计，不能用一次 HTTP 调用代替。

## 3. 模块级功能基线

### 3.1 工作台

- 汇总当前授权范围内的期初、转 U、消耗和期末。
- 提供近期结余趋势、草稿待确认、公式校验和负结余提醒。
- 提供到台账和报表的工作流入口。

### 3.2 投放公司与投放线

- 公司字段：名称、联系人、联系方式、备注、启用状态。
- 一家公司可包含多条独立投放线；投放线有名称、币种、费率/计算规则、启用状态。
- 支持搜索、创建、编辑、停用、删除；删除有历史台账的公司必须二次确认关联数据影响。
- 当前 Raj Data 已有本地公司/投放线雏形，但没有完整删除影响控制、公司范围权限和当前 ERP 的管理交互。

### 3.3 连续日台账与锁账

- 首次选择业务日期后开始录入，之后按天连续增加；默认承接上一日结余。
- 字段包含：昨日结余、转 U、有效转 U、消耗、汇损、服务费、回流、退款、其他、欺诈损失、当日结余、状态和备注。
- 汇损、服务费支持费率、计算基数、自动/手工覆盖与精度规则；欺诈损失有扣减来源规则。
- 支持计算预览、影响预览、单条/批量保存、确认、重新打开，以及按月校验、锁定和解锁。
- 当前 Raj Data 仅覆盖部分日结字段、计算预览和确认；缺少影响预览、批量保存、重新打开、期间锁定和完整计算规则。

### 3.4 导入中心

- 两条入口：Excel/WPS 多行多列粘贴，或 `.xlsx` 上传。
- 固定选择投放公司、投放线和业务年份；工作表支持列设置、空单元格/空行保留、日期多格式解析、费率本地计算覆盖。
- 服务端进行解析、校验和预览；预检冲突策略默认可跳过已有记录，确认后才写入台账。
- 提供标准模板、导入历史、任务行明细、原始文件下载和错误报告下载。
- 当前 Raj Data 已有粘贴/XLSX 预览和提交，但缺少标准模板、历史明细、源文件/错误报告、固定工作表交互和完整校验契约。

### 3.5 汇总报表

- 按日/按月、日期、公司、投放线、币种、状态筛选，并以用户可访问公司为默认范围。
- USDT/USDC 原币种分账；名义 U 仅是展示口径。
- 展示 KPI、指标趋势（柱状/折线/饼图）、可展开的日/月汇总行、完整金额口径和 Excel 导出。
- 当前 Raj Data 已有本地日/月查询和导出，但尚未达到完整筛选、趋势、展开明细和范围权限的功能等价。

### 3.6 用户、角色、范围与审计

- 一个员工可有多个角色；角色决定查看、录入、确认、导入、报表、审计、兑换码和系统管理等功能权限。
- 数据范围独立于角色，按全部或指定投放公司授予。
- 审计默认限定最近时间范围，按时间、动作、公司筛选；详情包含请求 ID 和前后数据。
- 当前 Raj Data 只有全局管理员边界和通用访问记录，未具备 ERP 的多角色、公司范围和 ERP 专用审计视图。

### 3.7 远端连接

当前 ERP 将远端主数据拆为两层：

1. 盘口：名称、编码、Base URL、启停。
2. 远端账号：归属盘口、账号名、加密密码/TOTP、会话检测状态、启停；并维护标签读取/同步和每账号的兑换金额档位预设。

Raj Data 的目标不是照搬该 ERP 的独立凭据体系，而是把现有 `SourceConfig` 演进为统一的盘口和远端账号主数据：

- 一个远端账号归属一个盘口；
- 分析只读、标签读取/同步、兑换码创建、兑换码发布/取消/下载必须成为服务端独立能力；
- 现有分析数据源和其默认凭据先兼容映射，不能丢失分析链路；
- 不创建 ERP 专属账号表、密码库或会话库。

### 3.8 兑换码管理（当前差异最大的模块）

云端 ERP 是远端作业编排中心，不是本地代码登记页。完整流程如下：

1. 选择兑换日期范围、兑换码类型（近 7 天充值或日充值）和一个或多个盘口。
2. 每个盘口自动使用其归属远端账号，并独立维护标签 ID 数组与兑换金额档位预设。
3. 按“日期 × 档位 × 盘口”生成远端兑换码配置任务；每项有独立描述/备注、远端配置标识和状态。
4. 任务组按盘口顺序串行创建；组、盘口子任务、执行批次、单条兑换码任务和代码下载记录都可追溯。
5. 支持创建进度、失败原因、重试、远端代码下载、当前盘口 Excel，以及多盘口多 Sheet Excel。
6. 配置全部创建后，每个盘口可分别选择立即发布或定时发布；立即发布可在冲突时按规则自动回退到定时发布，并支持取消/恢复本地发布占位。
7. 创建参数除标签和金额外，还包括发布环境、流水倍数、串行间隔、数量、累计充值条件、活动 ID、领取限制、有效期、银行卡/手机号/设备/IP 等控制项。

当前 Raj Data 的 `ErpRedemptionCampaign`、`ErpRedemptionCodeBatch` 和 `ErpRedemptionCodeIssue` 只实现本地活动、手工代码登记和“本地发布”状态，明确不调用远端；它不能作为该模块的迁移终态。

## 4. 源码接口差异

当前 ERP 源码已包含下列 Raj Data 尚未具备或未完整具备的契约：

| 领域 | 当前 ERP 契约 | Raj Data 当前状态 |
| --- | --- | --- |
| 台账 | 计算/影响预览、批量保存、确认/重开、期间锁定 | 部分单条本地台账能力。 |
| 导入 | 模板、两类预览、历史、行明细、原件、错误报告、提交 | 仅基础预览和提交。 |
| 报表 | 日/月查询与分别导出 | 基础查询/导出，缺少完整展示及权限口径。 |
| 远端连接 | 盘口、账号、检测、标签、档位预设 | 仅 `SourceConfig` 过渡配置。 |
| 兑换码 | 任务组、远端创建、下载、发布/取消/恢复、导出 | 本地活动/批次/代码登记。 |
| 身份与审计 | 多角色、公司范围、不可变审计 | 全局管理员和通用访问记录。 |

## 5. 正确的迁移顺序

1. **先固定基线。** 为本文件每一项建立 API、服务、页面和验收场景四列矩阵；未被矩阵覆盖的功能不标记为已迁移。
2. **先统一身份与远端主数据。** 在不破坏分析只读的前提下，完成盘口、远端账号、能力授权、公司范围和 ERP 权限模型。
3. **再迁移本地 ERP 域。** 依次完成投放公司/投放线、连续日台账和期间锁定、导入、报表、工作台、审计。
4. **最后重建兑换码编排。** 先落地任务组/子任务/状态机/导出/审计和 UI；远端客户端以受能力校验的适配器接入，不复用 ERP 的凭据体系。
5. **代码与数据分离切换。** 历史 ERP 数据只可经授权的只读导出后映射导入；生产数据库变更、备份、回退和窗口单独确认。
6. **远端写操作分阶段启用。** 代码具备能力不等于执行权限。连接检测、标签同步、远端创建、发布、取消和下载都需逐项得到明确授权并进行联调。

## 6. 完成功能等价的验收条件

- 云端 ERP 左侧每个业务入口在 Raj Data 中有真实页面、路由、权限和服务端实现，非占位页。
- 兑换码任务在组、盘口、批次和单条层级均能观察状态、错误、审计和导出。
- 所有金额字段、汇总口径、锁账与导入冲突行为都有自动化回归测试。
- 分析读取账号与 ERP 账号为同一远端账号主数据，ERP 权限不因共享账号而自动获得。
- 在没有远端业务操作授权时，界面和 API 均无法越权发起远端检测、同步、创建、发布、取消或下载。
- 只有完成基线矩阵逐项验收后，才可宣称“ERP 已迁移、融合完成”。
