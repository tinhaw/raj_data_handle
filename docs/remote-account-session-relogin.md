# 统一远端会话与重新登录

## 页面行为

- 检测连接：优先复用会话，读取兑换码配置列表来确认访问权限；不创建或发布兑换码。
- 重新登录：明确确认后强制更新这个账号的统一会话；可能使原会话失效。不补跑兑换码任务。
- 登录设置：每个账号单独保存。过期自动重登默认开启，业务请求需要会话时才登录；关闭后过期需手动登录。首次尚未连接的账号仍可随已授权业务登录。
- 定时重登：默认关闭，可设置 1～168 小时。保存不会立即登录，首次从保存时间起计算；之后从最近成功登录起计算。后台 worker 每 30 秒检查到期计划，关闭浏览器不影响运行。数据库内部以分钟换算保存，仅作为调度实现细节，不暴露给操作界面或 API。
- 已启用只表示账号开关；会话可用只表示存在未过期缓存，不替代连接检测成功。远端不提供可识别过期时间时，采用 30 分钟缓存，并在页面标明“估计”。

## 共享边界与保护

ERP 创建、发布、下载、标签同步和分析只读客户端共用现有 `remote_accounts` 会话，不新增账号或凭据体系。各业务原有能力校验保留，缓存命中不授予额外权限。

API 与 worker 通过数据库行锁串行化同账号登录；进程内另加异步锁。会话使用现有加密工具保存，身份绑定盘口 URL、账号和凭据版本。修改凭据后旧会话清除，旧请求不能继续用过时凭据登录。

明确的会话失效响应最多重登并重试一次；普通 403 权限拒绝不会触发重登。超时或不明确的远端写入结果不自动重试。另一个调用已更新会话时优先复用新会话，迟到的旧会话拒绝不会清除新会话。

同账号登录最小间隔 30 秒，失败指数退避，远端登录次数限制至少冷却 15 分钟，最长退避 1 小时。人工重登和修改凭据都不能绕过冷却。错误及审计仅保存固定安全文案，不保存原始响应、密码或访问令牌。定时策略不会自动重跑失败的兑换码任务。

## 迁移与发布边界

需要 `20260905_0043 → 20260905_0044`，在原账号表增加会话、冷却及策略字段。既有账号默认按需过期重登开启、定时重登关闭；不改变原凭据和业务任务，也不在迁移中连接远端。

本次开发仅在临时测试数据库运行迁移，没有执行现有数据库迁移或生产发布。后续上线需先备份 `data_handle`，按项目脚本单独执行结构迁移，再发布 API/worker/web。默认关闭定时登录，可先仅为一个账号开启观察，不新增全局兼容开关。

回退优先关闭定时策略并回退应用，保留新增列。结构降级会删除新的会话及策略数据，必须单独授权，不能盲目自动降级；保留原账号和凭据。
