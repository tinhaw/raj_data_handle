## 根因与边界

- 首个已证实的断点：`activateScheduledPublishIfDue` 仅根据本地时间到点，把明细从 `CREATED` 推进到 `PUBLISHED`；它没有查询远端执行结果。
- 页面将“下载失败”与“发布失败”合并成“生成失败”；撤销失败备注还会覆盖原发布回退原因。
- 审计分类：`missing_contract` / `tool_or_backend` 与 `presentation`；审计范围是本地状态机、统一执行器、远端任务列表及配置列表。完整配置内容因远端权限不足而未核实。
- 发布任务完成、兑换配置存在、兑换码已生成、文件可下载、兑换码已入库是不同事实，必须分别确认。

## 远端发布状态映射

| status | 远端含义 | 本地建议显示/行为 |
| --- | --- | --- |
| 0 | 待执行 | 等待远端执行；定时任务可提供撤销入口 |
| 1 | 写入配置 | 远端执行中；不标记成功 |
| 2 | 通知server异常 | 远端执行异常；保留原任务，不自动再次发布 |
| 3 | 发布完成 | 发布阶段完成，继续核验配置及兑换码 |
| 4 | 定时执行完成 | 发布阶段完成，继续核验配置及兑换码 |
| 5 | 定时任务撤销 | 已撤销；核对批次配置后才允许重新选择发布方式 |
| 其他/未找到 | 未知 | 待核验；不得解释为成功、失败或已撤销 |

状态 0 的撤销权限还须满足账号能力、当前操作权限及远端接口校验。查询失败、403、超时与业务执行失败分开呈现。

## 最小改进顺序

1. 增加通过统一账号执行器的只读“核验远端状态”入口，校验当前用户 ERP 权限、账号能力、盘口与批次关联。精确匹配任务 ID、环境与配置类型，分页未查全或未找到时返回未知，不猜测。
2. 立即发布返回 ID 后，以及定时到点后，都先查询远端任务状态；时间只用于决定何时检查，不作为完成证据。远端 3/4 才推进发布阶段。
3. 逐组核对配置 ID 与 group key，核对 `key_number`、有效期和标签范围；`make_code` 与配置 `status` 的语义尚未证实，不直接作为生成成功条件。配置未匹配显示“配置待核对”，不自动重建。
4. 实际导出数量与预期一致、号码非空且无重复，并成功入库后，才标记“生成成功”。发布完成但空文件显示“发布完成，兑换码未就绪”；有证据的导出错误显示“下载失败”。
5. 只对可重试的只读查询和下载做有限重试并退避；认证/权限失败停止自动重试。重试次数、最后核验时间和原因可见；不因空文件自动重新发布。
6. 明确显示“立即发布失败，已转定时”、原失败原因、定时时间；发布、回退、撤销和下载分别保留事件记录，后续错误不得覆盖此前证据。

## 实施前检查

- 目标：消除“到点即成功”的本地推断，提供可核验的阶段状态。
- 验收：远端等待、执行中、异常、完成、撤销、未知及查询不可用均有独立结果；两个现存任务可只读核验，不重复创建或发布。
- 影响范围：Python 远端只读契约与适配器、Java 兼容状态机与审计、ERP 兑换码页面。
- 风险：状态机跨服务变化；新增持久字段如确有需要，数据库迁移须与应用发布分开批准。
- 回退：按小步骤独立提交；可回退核验入口和展示层，不抹除原远端 ID、明细、兑换码和审计。不得通过回退恢复“无证据标记成功”。
- 功能开关：新增核验入口可先对选定盘口验收；旧时间推断不应作为核验失败的降级路径。
- 回归主题：远端状态映射、批次/账号/盘口隔离、分页精确匹配、定时与立即发布确认、未知与权限边界、空码/部分码/重复码、下载后入库、撤销竞态和审计保留。

## 本次实现

- 已新增统一账号只读核验入口：主 API `/compatibility-redemption/verify` 与兼容 API `/batches/{batchId}/remote-publish/verify`。读取远端状态、环境和配置类型，再核对各配置的 ID、兑换组与数量；权限检查复用兑换码下载能力。
- 未知、列表不可用、分页未查完均不得视为完成；配置查询失败保留已经核实的发布完成事实，单独返回配置核验错误。
- 生产下载入口先核验远端完成及配置匹配，再推进明细状态；网络请求前后的短事务重新读取批次，防止持久化上下文缓存把旧任务核验结果用于新任务。

- 原创建、发布与立即发布自动回退策略保持不变；发布后仅在核验完成且配置匹配时自动下载。不会因空码重建或再次发布。
- 撤销结果追加到原备注，避免覆盖原发布失败/回退原因。
- 本次不新增数据库字段或迁移；没有执行真实发布、撤销或兑换码导出。
- 本地验证：Python 50 项、Java 37 项、前端状态逻辑 3 项测试通过；Ruff、前端类型检查与生产构建通过。应用发布沿用本会话已获授权的目标、备份和回退流程。

后续可单独扩展有效期/标签核验及有限后台轮询；本次不根据尚未证实的 `make_code` 字段判定成功。
