# 远端后台发布后回到本系统下载

## 使用流程

1. 配置就绪且尚未取得真实发布 ID 时，任务列表和盘口明细提供“已手动发布”。多盘口任务在弹窗中选择实际发布的盘口。
2. 核对盘口、子任务与账号，从对应远端发布记录复制发布任务 ID。不是 ERP 任务号或配置 ID，不按最新一条记录猜测。
3. 点击“核验并关联”。待执行、执行中或已完成的有效远端任务可接管当前盘口。接管成功后本地状态为已提交发布，并不代表已生成兑换码。失败不会清除已有占位。其他盘口不受影响。
4. 关联成功后进入“发布与下载检查”；点击“下载兑换码”入库，再下载当前盘口 Excel。多盘口需分别处理，全部入库后可从总任务导出多 Sheet Excel。

打开填写窗口不会变更任务状态。关联与下载是两个独立操作，均不触发重新发布。关联成功但未下载完的任务，可从任务详情的核验和下载入口继续。

## 实现与边界

- 新增兼容 API `POST /api/v1/redemption-campaigns/batches/{batchId}/external-publication`，输入 `rowVersion` 与 `remotePublishTaskId`。
- 未取得真实 ID：允许待发布批次回填（包括系统自己的临时占位）。接管后停止该盘口后续系统提交和回退；已发往远端的请求不能撤回，迟到成功回执单独审计，不覆盖手动 ID。
- 已取得真实 ID：仅当服务端重新核验该盘口的原系统发布明确为 `FAILED`（失败）或 `CANCELLED`（定时任务撤销），且新发布已完成、配置全部匹配时允许换绑。查询失败、状态未知、等待中、执行中或已完成均不允许。操作入口在盘口的发布核验结果内，审计保留新旧 ID。
- 复用统一远端账号与下载能力校验，读取发布任务和配置列表；不新增账号、凭据或会话体系，不调用远端发布、创建或撤销接口。
- 精确核验操作者指定的远端任务 ID、环境、配置类型和任务状态。已完成时另核验本批次每条配置 ID、兑换组标识、兑换码数量；未完成时仅登记跟踪，下载仍需完成态和配置核验。远端列表不提供发布任务包含的完整配置清单，须由操作者选择对应发布任务。
- 核验前后检查批次版本、状态、账号与配置快照，避免将过期核验结果用于变化后的批次。成功关联写入 `remotePublishMode=EXTERNAL`、远端任务 ID 与独立审计事件；`publishedAt` 记录本系统确认时间，不冒充远端实际发布时间。
- 后续下载继续逐次执行既有远端完成及配置匹配检查、代码数量/内容校验和本地入库，完成后才允许完整 Excel 导出。
- 无新增字段或数据库迁移。回退应用不删除既有关联或已下载兑换码；旧版本仍使用已保存的远端发布任务 ID 核验下载，可能无法显示新的发布方式文案。

## 2026-11-27 换绑发布门禁（未上线）

- 本地使用 Spring HTTP 集成测试、H2 和模拟远端账号执行器：以原发布失败或已撤销为起点，提交新发布任务 ID、复核配置、下载并入库，调用实际 Excel 导出接口，再解析工作簿核对码值。没有向真实盘口发布、下载或换绑。
- 发布目标为 Raj Data Handle 的 ERP 兼容服务与 Web，不是 Wheel Review。此次换绑不需要结构迁移。不要从有其他未发布改动的工作区整包部署，也不要只发布前端。
- 发布前核对线上基线，从该基线提取本次改动并重新构建、复测；保留上一版 Web、ERP 镜像及运行配置，确认数据库已有可用备份或 PITR。保留既有主 API 的能力，包括独立的不存在性核验，不把本地其他 API 改动带上线。
- 经确认维护窗口后使用项目发布脚本。上线验收先检查健康、静态资源及明细读取，不以真实任务试换绑；对真实任务换绑另需操作人确认新 ID。失败时恢复上一版镜像和运行配置，不降级数据库、不清库存、不反向覆盖已记录的发布 ID。
