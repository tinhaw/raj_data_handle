本地未命中且用户勾选远端查重时，按盘口串行查询，每盘口整批码共享两轮完整稳定目录扫描，不逐码重复扫描。检查包含本系统未登记的远端同码；远端查询的 gift_code 过滤参数已知不可依赖，因此不使用它判断不存在。分页、数量、重复记录、目录变化、权限或超时问题均返回查重失败；不会静默退回本地模式继续创建。扫描仅代表当时可见目录，不锁定后续远端人工操作。

普通随机码不进行特殊码预查重。表单查重期间禁止重复提交和改动参数；用户取消最终生成确认不会创建任务。

## 执行边界

新增 Java `/redemption-campaigns/groups/duplicate-check` 预览接口（VIEW + GENERATE）和 Python `/remote-accounts/compatibility-redemption/duplicate-check` 内部读取接口（GENERATE + 统一账号 ERP_REMOTE_CHECK）。账号、凭据和会话沿用现有主数据体系，没有新增会话或能力开关。

真正提交创建时在现有同盘口/同码锁内再次做本地冲突检查，避免绕过预览、在预览后出现冲突或旧页面直接提交时悄悄复用。命中返回 `LOCAL_REDEMPTION_DUPLICATE`，不调用远端创建、复用核验或目录扫描。原有「核验并复用」「核验缺失并重建」仍是明确操作入口，沿用原来的回读、参数确认和权限检查。已确认的复用关系、有效回执及实际奖励待核验状态不会因重试再次创建配置。

此变更不把「发现同码」当作删除授权，也不串接删除后自动重建。兑换码配置主动删除与意外缺失仍按既有设计区分。
