## 判断与证据

- failure type：`tool_or_backend`，远端创建契约不匹配；是否属于新回归尚未确认。
- audit depth：local；node containment：not_applicable。
- first broken link：远端配置创建时，类型必填校验拒绝请求。
- root cause：已证实的直接原因是远端未收到或未认可所要求的兑换码类型；页面保存了“近 7 天充值”，不能归因为操作者没有选择本地类型。
- 本地 `UnifiedRedemptionRemoteExecutorClient.create()` 不传递批次 `redemptionType`；`RemoteCreateCommand` 也没有该字段。
- `RajAdminGiftCodeAdapter.create_configuration()` 向 `/api/common/giftCodeConfig/save` 构造的 JSON 包含用户类型、标签、金额和生效时间等字段，没有显式兑换码类型字段。`_success_payload()` 会将远端业务失败响应的 message 转为错误，兼容执行服务继续将其传回任务。
- 以上源码与页面错误一致，支持“当前创建请求与远端类型必填契约不兼容”的判断；尚未读取实际生产请求及远端接口定义，不能确认远端要求的字段名、枚举值，或其是否近期发生变更，也不能假定本地“近 7 天充值”枚举可直接作为远端类型值。
- `generateCodes()` 在单条请求失败后记录失败并继续后续配置，没有同类错误提前终止，因此一次共同的参数问题可扩散为全部 150 项失败。
