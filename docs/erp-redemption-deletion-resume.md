# 批量删除中断后的恢复

状态：2026-11-13 已完成本地实现与回归，尚未部署。本次不新增数据库迁移，不进行真实删除。

## 用户流程

1. 再次打开任务的「批量删除」，读取已保存进度，不自动提交删除。
2. 点击「核对并预检剩余项」。先只读核对旧的未决请求，再逐项预检剩余配置。关闭弹窗会停止后续项，已提交的请求仍可能完成。
3. 表格分别显示远端存在性、核对时间、执行状态和共享任务。存在性和执行状态是两个维度：配置可能仍存在，同时尚未执行删除。
4. 展示本次可处理数量和排除数量。用户勾选确认、输入任务号后，继续处理本轮通过预检的项。原任务已删除项自动跳过；原库存、配置身份、共享引用、历史删除记录均保留。
5. 旧页面无法继续被新预检取代的旧批次。正在处理的请求不允许被立即重复启动；任务配置 ID 范围变化会阻止沿用旧删除范围。

| 远端核对 / 执行事实 | 展示与处理 |
| --- | --- |
| 删除后确认原 ID 不存在 | 已删除 / 已确认不存在；跳过 |
| 请求响应丢失，随后只读确认原 ID 不存在 | 登记已删除；不重发 DELETE |
| 原 ID 仍存在，尚未提交删除 | 未执行；重新预检并统一确认后继续 |
| 原 ID 仍存在，但旧删除请求结果不明 | 显示仍存在、旧请求未决；本轮排除，可继续其他未执行项 |
| 读取超时、权限失败或结果不可靠 | 无法确认；不能据此声称已删除 |
| 原配置指纹变化 | 身份或参数变化；禁止沿用旧确认，不能误删同码新配置 |
| 之前已明确保留 | 保留既有决定；旧删除请求不重放 |

“仍存在”是带时间的观测，不等于旧请求已结束。此实现不解除一次性执行保护，不重置 `remote_attempted`，也不把读到 PRESENT 当作新的删除授权。未决项仍须只读核对；其余预检通过的项可以继续，避免一项未决阻断全部工作。

## 持久化与兼容

- 原审批快照 `snapshot_json`、原远端身份和指纹 `remote_json` 保持其原用途。
- 新增 `REDEMPTION_DELETE_OBSERVED` 审计事件，保存原配置 ID、PRESENT / ABSENT / IDENTITY_CHANGED / UNAVAILABLE、服务器核对时间及安全说明；追加记录而非覆盖原请求证据。
- 每次批量确认另存 `approvedItems` 和 `excludedItems`，保留本次批准的配置、共享任务以及未批准项状态。
- 删除视图和批量条目保存 `observation`，刷新和重新进入可以看到核对事实；旧记录没有该字段时显示“尚未核对”，不伪造核对时间。
- 执行进度只按已确认删除计算，不把检查失败或 UNKNOWN 算成删除完成。仍有 UNKNOWN / BLOCKED 时保持 PAUSED；明确保留或无配置的项单独展示。
- 保留线上已存在的明确保留（KEPT）处理，以免恢复功能覆盖旧请求保护及用户已作出的保留决定。

## 修复前核对与风险

- 主目标：删除中断后可以核对持久化事实，并在重新确认后仅继续安全的剩余项。
- 首个缺口：`reconcile` 对 PRESENT 仅返回 UNKNOWN，未保存本次存在性和时间；弹窗只展示单一执行状态，旧进度算法将 UNKNOWN / BLOCKED 当作已完成处理。
- 分类：missing_contract；跨远端回读、本地持久化和页面呈现的完整链路。仅核对本地实现和模拟远端，本轮没有线上证据采集。
- 影响范围：兑换码删除服务、批量任务恢复、删除弹窗和相应 API 类型；不改变同码创建、库存身份和远端写入协议。
- 风险：中高（永久删除入口）。继续使用原一次性执行保护、原 ID 与指纹约束、独立权限和显式确认，不增设自动删除路径。
- 回退：本轮修改前文件保存于 `output/verification/redemption-delete-resume-20261113/before`；尚未部署，无生产状态需要恢复。未来发布需独立准备备份和回退方案。
- 灰度：先验证预检、取消和刷新流程；真实删除需要另行确认目标。未启用新的远端执行协议，不需要新特性开关。
