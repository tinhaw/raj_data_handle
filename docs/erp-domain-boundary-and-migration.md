# ERP 域边界与迁移约定

> 状态：代码迁移设计基线
>
> 日期：2026-08-17
>
> 适用范围：将 `raj-ads-manage` 的 ERP 台账、导入和兑换码模块迁入 Raj Data Handle。

## 1. 迁移边界

本项目将承载两个业务子域，并使用一套统一的远端盘口与账号主数据：

| 子域 | 职责 | 对远端系统的边界 |
| --- | --- | --- |
| 数据分析与对账 | 从 RajWin / RajLuck 读取订单并做本地分析、缓存和对账 | 保持只读；使用统一账号体系中被授予分析读取能力的账号。 |
| ERP 业务 | 本地维护台账、导入记录与兑换码批次 | 台账、导入和兑换码本地写入会迁入；需要远端兑换操作时，使用同一账号体系中被授予兑换能力的账号。 |

ERP 本地能力的生产发布与数据库结构迁移，必须在单独确认目标环境、备份/回退方案和执行窗口后执行；不得发起任何远端业务操作。

## 2. 统一的盘口与远端账号模型

以现有分析侧“数据源与盘口”作为唯一的远端账号管理入口升级，而不是为 ERP 复制一套账号系统。

| 概念 | 当前状态 | 迁移后的职责 |
| --- | --- | --- |
| 盘口/来源 | `SourceConfig` 同时保存 `source_id`、展示名、Base URL、时区、币种和默认读取凭据。 | 保留来源标识、展示信息、Base URL、时区和币种，作为统一远端账号的归属盘口。 |
| 远端账号 | 每个 `SourceConfig` 现存一组读取凭据。 | 独立为统一账号记录；一个盘口可关联多个账号，每个账号保存用户名、密码、TOTP、会话及健康状态。 |
| 账号能力 | 分析读取由现有来源配置隐式限定。 | 显式维护账号能力，如 `analysis_read`、`redemption_remote`；同一账号可以被授予多项能力，但不会自动扩权。 |

ERP 最新实现中的 `marketId` 关系保留为统一模型的“账号归属盘口”关系。兑换码批次记录未来保存统一远端账号的标识，以保留历史追溯；分析任务则保存来源标识与实际使用账号的快照。

凭据只在统一账号记录中保存一次。现有 `SourceConfig` 中的密文在获批的数据迁移中以受控方式重加密至统一账号作用域；不得复制明文、不得将会话搬运到浏览器，也不得因共享账号绕过能力检查。

## 3. 迁移顺序

1. 迁入导航、页面归属和纯前端交互骨架，统一为同域路由。
2. 迁入 ERP 的请求/响应契约、校验规则、权限点和审计语义，并接入统一远端账号能力模型；此阶段不调用远端服务。
3. 提交数据库结构变更方案：从 `SourceConfig` 的默认读取凭据迁至统一账号记录，明确历史数据策略、重加密、备份、回退方案和执行窗口；获得单独授权后才能生成并运行迁移。
4. 迁入本地台账、导入和兑换码写入实现，并完成本地回归测试。
5. 对每一种远端操作分别评审最小权限、审计、幂等、失败恢复和人工确认；获得单独授权后才可启用。

## 4. 统一账号下仍须隔离的内容

- 不复制或另存第二套密码、TOTP、访问令牌和会话；所有凭据写入统一账号记录且永不回显。
- 不以账号的 ERP 能力替换或扩大分析同步权限；每个调用点必须校验所需能力。
- 不把兑换码发布、标签同步或远端登录接入分析同步任务；账号统一不代表任务和权限统一。
- 不读取、写入、迁移或复用 `review_recheck` 的数据库、Redis、容器、卷、配置或密钥。
