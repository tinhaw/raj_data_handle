## 证据与首次断点

- case：管理员在 `/erp/redemption` 看见“共 0 个兑换码组任务”和首次创建提示。
- failure type：`query_or_read_model` + `presentation`；重复读取目录的代码在本次门槛修复前已存在，尚无发布前同规模性能对照，不能将其直接归因为迁移删除或新业务逻辑回归。
- audit depth：full；范围为本地事实、查询接口、浏览器结果及界面状态，不触发远端创建或发布。
- node containment：shared_layer，影响 Java 兼容账号目录读取和 Vue 任务列表状态；不涉及 LLM 节点。
- 首次明确失败：前端 15 秒请求超时。已在用户当前登录页面刷新并捕获 `timeout of 15000ms exceeded`；超时后仍显示“0 条”和“还没有兑换码组”。

生产只读查询确认 84 个活动、378 个档位、47 个主任务、84 个批次、5807 条配置记录仍在。以相同登录身份直接打开活动接口返回活动数据，批次 overview 接口最终也返回数据，但浏览器首次导航在 10 秒内未完成，原页面 Axios 的 15 秒预算被耗尽。后台 5 分钟内记录到 507 次统一账号目录 GET。

`batchOverviews()` 对每个批次调用 `remoteDirectory.find()`；`CompatibilityRedemptionRemoteDirectory.registry()` 每次都经内部 HTTP 读取统一目录。84 个批次会重复读取相同目录。定向回归以 84 次账号解析加 1 次标签核对复现：修复前期望 1 次请求，实际 85 次。

第二断点是展示：`loadCodeGroups()` 捕获异常时只显示短暂消息，没有持久失败状态；初始数组为空，于是错误路径渲染为首次使用的空列表。
