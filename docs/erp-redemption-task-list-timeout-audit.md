# 兑换码任务列表超时误显示为空

日期：2026-11-01。生产版本：共享充值门槛修复 `aa7f93a`，数据库 `20261101_0052`。

## 证据与首次断点

- case：管理员在 `/erp/redemption` 看见“共 0 个兑换码组任务”和首次创建提示。
- failure type：`query_or_read_model` + `presentation`；重复读取目录的代码在本次门槛修复前已存在，尚无发布前同规模性能对照，不能将其直接归因为迁移删除或新业务逻辑回归。
- audit depth：full；范围为本地事实、查询接口、浏览器结果及界面状态，不触发远端创建或发布。
- node containment：shared_layer，影响 Java 兼容账号目录读取和 Vue 任务列表状态；不涉及 LLM 节点。
- 首次明确失败：前端 15 秒请求超时。已在用户当前登录页面刷新并捕获 `timeout of 15000ms exceeded`；超时后仍显示“0 条”和“还没有兑换码组”。

生产只读查询确认 84 个活动、378 个档位、47 个主任务、84 个批次、5807 条配置记录仍在。以相同登录身份直接打开活动接口返回活动数据，批次 overview 接口最终也返回数据，但浏览器首次导航在 10 秒内未完成，原页面 Axios 的 15 秒预算被耗尽。后台 5 分钟内记录到 507 次统一账号目录 GET。

`batchOverviews()` 对每个批次调用 `remoteDirectory.find()`；`CompatibilityRedemptionRemoteDirectory.registry()` 每次都经内部 HTTP 读取统一目录。84 个批次会重复读取相同目录。定向回归以 84 次账号解析加 1 次标签核对复现：修复前期望 1 次请求，实际 85 次。

第二断点是展示：`loadCodeGroups()` 捕获异常时只显示短暂消息，没有持久失败状态；初始数组为空，于是错误路径渲染为首次使用的空列表。

## 修复前检查

- main goal：恢复列表读取，并区分“加载失败”和“确实没有任务”。
- acceptance points：同一次 HTTP 请求最多读取一次账号目录；后续请求必须重新取目录；不同用户隔离；失败不缓存；超时提示持久显示；刷新失败保留已有记录。
- impact scope：兼容目录适配器、兑换码列表加载函数和错误状态；不改金额、创建、发布、下载及数据库结构。
- risk level：低至中；请求内复用认证目录快照，需要验证请求和用户隔离。
- rollback strategy：保留部署前源码、配置及应用镜像，必要时回退本次应用修复；数据库保留 `0052`，不降级。
- regression plan：`query_readback`、`error_boundary`、`counterparty_isolation`（请求与用户边界）；目录调用次数、下一请求权限更新、跨用户和失败重试；前端首次超时、刷新失败保留记录、成功重试清错；Java 全量和 Web 构建冒烟。

## 本地修复与验证

目录快照仅挂在当前 `HttpServletRequest` 的服务端属性中，不使用静态全局、用户会话或跨请求缓存。读取失败不会写入缓存。新请求照常重新验证目录、账号和标签。

页面增加持久的读取错误提示，首次失败显示“任务读取失败”，不显示首次创建空态；已有列表在刷新失败时保留，成功重试清除错误。

Java 目录定向测试 6 项通过，包含 84 个批次共享同一次读取、新请求重新读取、不同用户隔离和错误不缓存。兑换码前端测试 39 项通过，Vue 类型检查及合并 Web 构建通过。Java 全量测试通过。

首次根目录执行 `npm run typecheck` 因根目录没有 package.json 未进入检查；改在实际 Web 工程执行后通过，不属于业务失败。

本次源码内的重复目录读取是先修复的性能断点。上线后的真实耗时、列表可见数量仍需使用相同登录页面验证；本地调用次数改善不能替代生产验收。无需功能开关，验收先使用管理员的只读列表请求；若行为异常，回退应用即可。
