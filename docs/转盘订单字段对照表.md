# 转盘订单字段对照表

本表以 `data_templates/转盘订单/转盘订单列表.txt` 的远端列表响应和
`导出数据列表 (7).xlsx` 的列为基线，供确认“转盘订单”页面的本地缓存、明细、渠道汇总与
两小时申请人数图表口径。页面只读取本地缓存；所有远端调用都是只读的后台刷新或管理员主动
刷新字典。

## 1. 刷新与字段安全边界

- 转盘订单列表按审核状态 `0`、`1`、`101`、`2`、`3` 分别分页读取并按
  `source_id + ID` 合并；若同一订单在读取期间发生状态变化，采用最后读取的终态记录。
- 自动任务默认在每两小时边界后的五分钟运行，读取前一个完成时段，并从前一业务日
  `00:00:00` 回查到该时段结束，以补齐延迟审核。管理员可在“系统配置 → 转盘订单远端同步”
  修改刷新间隔（1、2、3、4、6、8、12 或 24 小时）、远端分页大小（10、20、30、50 或
  100 条 / 页）及自动回查范围；手动刷新仍可选前天、昨天或今天。
- 转盘订单仅缓存下表中的分析字段，绝不保存远端完整响应、账号、手机号、昵称、IP、审核理由、
  审核人 UID 或姓名等未列字段。
- 用户渠道来源仅缓存 `source_id + uid + channel_id`、解析状态和下次重试时间；不缓存完整
  用户资料。首次解析失败在 30 分钟后重试，单个盘口最多并发 8 个 UID 查询。

## 3. 数据字典与渠道来源覆盖刷新

| 字典 | 代码 → 展示值 | 页面用途 | 更新方式 |
| --- | --- | --- | --- |
| `spin_order_status` | `0` 待审核；`1` 审核通过；`101` 自动审核通过；`2` 已拒绝；`3` 已挂起 | 状态标签、筛选、汇总 | 盘口创建与数据库迁移时写入固定值；只读展示。 |
| `user_source_channel` | 用户详情 `channel_id` → 远端 `channelList` 中的渠道名称 | 渠道来源展示与筛选 | 管理员在“数据字典 → 渠道来源”选择盘口后点击“覆盖刷新”。 |

“覆盖刷新”安全语义如下：先完整读取并校验远端 `channelList`（不能为空、代码和名称不能为空、代码不能重复），再在**同一数据库事务**中删除该盘口的旧 `user_source_channel` 字典并写入新字典。远端读取或校验失败时不会清除旧字典；其他盘口的字典不受影响。远端的 `-` 聚合伪选项不会写入本地，也不会出现在业务筛选中。

## 4. 汇总指标口径

渠道汇总的一行固定按下列键分组：

```text
source_id + 申请日期（盘口业务时区） + spin_config_id + channel_id
```

| 页面指标 | 计算公式 |
| --- | --- |
| 申请总订单数 | 当前分组内去重后的订单数。 |
| 审核通过订单数 | `status in (1, 101)` 的订单数。 |
| 待审核 / 已拒绝 / 已挂起订单数 | 分别为 `status = 0 / 2 / 3` 的订单数。 |
| 订单通过率 | 审核通过订单数 ÷ 申请总订单数；分母为零显示 `—`。 |
| 中奖人数 | 当前分组内按 UID 去重的订单申请人数。 |
| 审核通过人数 | 当前分组内至少有一笔 `status in (1, 101)` 的 UID 去重人数。 |
| 人数通过率 | 审核通过人数 ÷ 中奖人数；分母为零显示 `—`。 |
| 每 2 小时申请人数 | 同一业务日期、两小时桶、转盘配置和渠道来源组合内的 UID 去重人数。图表不跨组合相加，避免重复 UID 被错误累加。 |

“审核通过”在所有页面和图表中均包含人工审核通过 `1` 与自动审核通过 `101`。
