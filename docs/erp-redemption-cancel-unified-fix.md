# ERP 撤销定时发布：统一账号链路修复

## 问题与证据

- 案例：任务 `202609180001` 点击撤销，提示 `ERP 兼容模块的远端操作尚未启用：remote_cancel`。
- 分类：`business_regression` / `tool_or_backend`；局部审计定位后沿 Java → 主 API → 远端适配器核对契约，节点隔离分类为 `not_applicable`。
- 首个断点：Java 撤销入口无条件进入旧凭据客户端的 `RemoteOperationGate`。生产统一身份模式下该门禁止旧客户端；创建、发布和下载已经接入统一执行器，撤销遗漏。
- 此提示发生在远端调用之前，因此这次失败请求没有撤销远端任务。线上当前状态及部署版本尚未直接核验。
- 用户提供的请求示例仅作为接口证据：`POST /api/common/publishTask/cancelAuto`，JSON 数字字段 `id` 为远端发布任务 ID，成功要求 `data.ret = 1`。示例中的会话资料不复制到实现或测试。

## 修复与验收范围

- Java 按已有统一执行器分支转发撤销；保留独立回归夹具的旧客户端门禁。
- 主 API 增加内部 `/api/v1/erp/remote-accounts/compatibility-redemption/cancel`，校验 ERP 生成权限、统一账号和盘口启用状态、`ERP_REDEMPTION_CANCEL` 能力及当次执行确认。
- 请求采用批次已保存的远端任务 ID，不采用本地业务任务编号。统一账号凭据仅由主应用使用。
- 保留批次版本、未来定时时间、任务 ID 和账号盘口一致性校验；远端确认成功后恢复 `READY_TO_PUBLISH`，失败保留原发布状态及任务 ID，并记录审计。
- 不新增数据库结构或切换生产身份模式。现有统一执行器是否可用决定客户端分支，不新增开关，也不关闭原安全门。

## 本地验证与上线边界

- 主题：撤销确认与状态回读、账号隔离、权限拒绝、接口错误边界、撤销后立即发布，以及相邻创建/下载流程。
- Python 相关测试 29 项通过；Java 相关测试 30 项通过；变更 Python 文件 Ruff 检查通过。
- 测试使用 SQLite/H2、模拟远端 HTTP 和模拟执行器，没有向线上发出撤销或发布请求。
- 风险：新增真实远端撤销入口，需要生产发布后才能生效；远端不可用或拒绝时不会声明撤销成功。
- 回退：代码改动可独立回退；生产发布前需留存当前源码、镜像及运行配置，失败时通过项目发布脚本恢复旧应用版本。无需数据库迁移。
- 发布授权：用户已确认提交、推送并立即部署到 `analysis.ailuckdg.com`，按上述方案备份及回退，不执行数据库迁移。发布后仍需核验原任务是否处于可撤销时间内；本次部署不代替用户执行远端撤销或立即发布。
